# Batch balances (local only)

**Try it without an account.** From `_local/accounts`, run `python3 server.py --demo`. Open the printed loopback address, then **Batch balances → Discover accounts for review**. This mode creates a disposable database with a manual joint card and 12 fictional source balances across three institutions; it never loads Bridge credentials or uses the normal dashboard database. Stop with Ctrl-C. `--demo`, `--bridge`, and `--db` cannot be combined.

**One short mode cue is always shown.** It distinguishes **Fictional demo** (discarded on exit, synthetic), **Local manual** (no provider; saved on this computer) and **Configured** (e.g. SimpleFIN Bridge; not live; no automatic sync). None is live: discovery and refresh are explicit, balances-only requests; nothing fetches on page load; nothing changes until you explicitly **apply reviewed selections** or run a **refresh** on checked rows.

**Scannable, nothing silent.** Discovery is ordered first; after applying, linked balances come first with a prominent Refresh. The batch form is full-width; per-row detail uses native **<details>**; match candidates show local account, owner, side, currency, balance and date readably; a default-owner control has an explicit blank placeholder with intentional **Unspecified**; no implicit match; fixed linked identity. Discovered rows are a scannable list, not a wall of fieldsets. Each row shows institution, account name, an explicitly **signed** amount, currency and an *as-of* date. Nothing is pre-checked: no row is included, no destination is chosen, no sign is assumed, no owner is assumed, no link is created, and refresh checks nothing for you. Match/create, sign and owner choices are readable, and extra per-row detail uses a native **<details>** disclosure (keyboard-accessible, no scripts, visible expand indicator). On a validation error, your selections are kept so you can adjust and re-apply. Dated balances are shown without rounding; currencies are never converted.

1. Click **Select all review rows**, then uncheck any to skip. This only changes the checkboxes; it neither fetches nor writes accounts. Set a default owner for **new** accounts. For Cedar Credit's negative card balance choose **Match #1: Household card** and **Debt**. The local Joint owner, nickname, type and manual update instructions stay intact.
2. For the remaining fictional rows, explicitly choose **Create new account** and **Asset**; try a different owner on one. In real use, compare the displayed institution, currency, signed amount, date and local record; if unsure, leave it out. A positive number is not proof of an asset. Debt stores the magnitude and subtracts it once.
3. **Apply reviewed selections** saves all decisions together or none. Check the inventory: 12 accounts, not 13; USD 50.69 net and JPY 2,004 net. Applying the same review twice cannot create another row.
4. Return to Batch balances. **Linked balances** is a scannable list; nothing is checked for refresh. Check only the rows you want and use **Refresh selected balances**. One balances-only request covers all connections; only checked links may change locally. **Balance as of**, **last operation status** and **last checked (UTC)** are shown as separate facts, and each linked row links to Edit. There is no automatic background refresh. The static demo will report unchanged.

### What can change

Links use a digest of the provider namespace, connection ID **and** account ID. Names are for people, not matching. No automatic creation on refresh. A missing, malformed, duplicated or failed item keeps its local snapshot. A genuine dated zero is valid; a missing balance isn't zero. Unknown or unscoped provider errors can hold the whole batch. Local dates come from provider timestamps in this computer's timezone; comparison also uses the full source timestamp. No cross-currency conversion, and no rounding away excess precision.

If a linked balance, side, currency or date has been edited locally (even backdated), refresh leaves it alone. Discover again to compare and explicitly confirm; older snapshots cannot replace newer ones. Sign reversals, an initial zero becoming nonzero, and changed amounts at the same timestamp require review. Matching requires the local side and currency to agree. A changed currency is not a currency conversion. If an institution reissues an ID, don't create a second account just to clear an error: leave it out. There is no automatic relinking, merging or resurrection of deleted local rows. Discovery is held in memory until another fetch, successful apply or restart; saved links and quota are in SQLite. Review supports up to 200 source balances.

### Optional SimpleFIN Bridge (not required for manual entry)

The adapter implements the [v2 draft protocol](https://www.simplefin.org/protocol.html) and [Bridge developer guide](https://beta-bridge.simplefin.org/info/developers). Only offline injected responses have been tested. No enrollment, trial, live claim, live balance, pricing, or institution/loan coverage was verified. Check fees, coverage and data-sharing terms yourself **before** deciding whether to enroll. Manual snapshots remain available for unsupported accounts. No hosted service, sign-in, scheduled polling, transaction download, or custom-currency URL fetch.

**Only if you decide to use an existing Bridge setup token:** run `python3 bridge.py setup` in a private terminal. Enter the one-time token at the hidden prompt, never in a shell command, browser form, environment variable, Git file or chat. The CLI POSTs the decoded claim URL once. A failed claim can mean the token has been used or compromised; disable it at Bridge. The access URL is a read credential, not a link to visit. It is saved unencrypted in `~/.local/share/planner-accounts/bridge.access` (0600; owned private 0700 directory outside Git). Protect that directory and its backups. Existing credential files are not overwritten.

Run `python3 server.py --bridge` to opt the normal local dashboard into using that credential. Opening the page does not fetch. Discovery or refresh requests v2 balances only with Basic auth over verified HTTPS. Only the exact Bridge hosts `bridge.simplefin.org` and `beta-bridge.simplefin.org` are accepted; redirects and custom hosts fail closed. A rolling 24-hour limit of 24 attempted reads per dashboard database includes discovery, refresh and failed reads across restarts. Bridge is intended for daily updates; other apps may also use quota. Payment-required, revoked access and provider issues leave balances in place. Diagnostics use local messages, not raw provider error bodies.

The adapter appends `/accounts` to the returned `/simplefin` root, preserving safe nested path segments. Treat that path as private too. Dot segments, empty internal segments, percent escapes in the path, queries and fragments are rejected, not normalized. A different nested root is treated as a separate source rather than assuming its account IDs refer to existing links.

Restart without `--bridge` to stop access from this app. To revoke external access, disable the app token at Bridge, then remove the local credential file; deleting only the file does not revoke it. The local snapshots and links remain. Do not share the DB or expose the loopback server.

**Verification (fictional data only):** from this directory run `python3 -m unittest discover -v`, then with Playwright and Chrome installed run `python3 -m unittest -v browser_bulk browser_save browser_preview`. Browser acceptance injects an offline Bridge transport, restarts the HTTP server on the same temporary database, and checks dates, exact totals, partial results, and absence of a fictional secret in requests, page, logs and database.
